# 2D 模板规范（单文件 main.js）

适用：2048/三消/跑酷/弹珠/合成类 2D 休闲游戏。原生 Canvas 2D，无框架，无依赖。

## 章节顺序（必须照此顺序生成，不许打乱）

### 1. 常量配置
网格尺寸、动画时长、速度、分数等调参集中顶部 `const`。例：`GRID_SIZE`、`ANIMATION_DURATION`。

### 2. 视觉调色板
数值/类型 → 样式的映射表（如 `TILE_STYLES`：渐变起止色、辉光色、前景色）。
超出表范围的值用确定性 fallback（如按 `log2` 取霓虹色循环），不许裸奔。

### 3. 资源加载
`new Image()` 懒加载；绘制时判 `complete && naturalWidth`，没加载完画纯色底兜底。

### 4. 音频系统
- HTMLAudio 播 MP3（BGM 循环 + 音效），WebAudio 振荡器合成简单音效
- 首次用户交互时解锁（`initAudio` 只跑一次）
- 每次 `play()` 后跟 `.catch(()=>{})`；短音效用 `cloneNode()` 实现重叠播放
- 移动端加 `navigator.vibrate` 触觉反馈（判存在再调）

### 5. 全局状态
模块级 `let`：棋盘/分数/最高分/是否结束/粒子数组/动画队列/震屏强度/浮字数组/连击计数与计时器。
最高分 `localStorage` 读写，key 带游戏名前缀，读带 `'0'` fallback。

### 6. Canvas 与自适应布局
- `resize()`：DPR 上限 2，`ctx.setTransform(dpr,0,0,dpr,0,0)`
- 宽屏强制居中 520px 竖列：`UI_W = Math.min(W, 520)`，`UI_X = (W - UI_W) / 2`
- 棋盘尺寸由可用宽高取最小，格子 `GAP`/`CELL` 由此推导，不许写死像素

### 7. 核心逻辑
纯函数优先：滑动/合并/生成/胜负判定与绘制解耦。多方向操作统一成"取行→变换→写回"（getRow/setRow/resolvePos 模式）。

### 8. 粒子/特效系统
`spawnXxxParticles(x, y, value)` 模式：数量/速度/颜色随数值缩放；粒子自带重力、透明度衰减、越界回收。

### 9. 绘制函数族
`drawXxx` 一族：背景/Header/棋盘/单位/粒子/浮字/结算/标题屏/徽章/连击条。
每个绘制函数只读状态不改状态（动画进度推进除外，且用固定步长）。

### 10. 主循环
`requestAnimationFrame(loop)`：清屏 → 震屏衰减（`screenShake *= 0.9`）→ 按状态分发绘制 → 连击计时器递减。
动画用帧内固定步长（如每帧 +16ms）推进，不用 delta 插值。

### 11. 统一输入
touchstart/touchend、鼠标拖拽、键盘方向键走同一套 `handlePointerDown/Up`。
滑动阈值 28px 判定方向；首次点击 = 开始游戏；结算页点 RETRY 热区或按 R 重开。

## Juice 强制清单（至少 3 种）

- [ ] 粒子爆发（合并/消除时）
- [ ] 屏幕震动（带衰减，大连击加码）
- [ ] 浮动得分文字（上飘 + 透明度衰减）
- [ ] 连击系统（时间窗口 + 衰减条 + 加成公式）
- [ ] 新单位缩放动画 / 合并闪光
- [ ] 标题屏呼吸/弹跳动画

## 标题屏与结算屏

- 标题屏：Logo + 玩法演示小图 + 脉冲"点击开始"按钮 + 一句话玩法说明
- 结算屏：GAME OVER + 分数/最高分 + RETRY 按钮（热区对象存下来给输入用）

## 质量红线（2026-10-13 审计 Army Rush 3D 后补入）

1. **零死代码**：加载的资产必须被使用；每个方法必须被调用；未使用的 import 删除。
2. **胜利条件必填**：胜利/通关条件必须写进需求，结算不许只有失败分支。
3. **难度曲线必填**：速度/敌人强度/生成频率至少一维随时间递增。
4. **战斗必须有悬念**：不许 1 换 1 纯消耗定胜负（至少引入伤害/攻速/克制其一）。
5. **数值自检**：开局数值必须能活过第一个敌人（最小收益路径 vs 最大敌人强度）。
6. **注释必须与代码一致**，写错注释不如不写。
